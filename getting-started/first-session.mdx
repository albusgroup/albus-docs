title: Run your first session
description: Run an agent session from the CLI, Python, TypeScript, or cURL.
---

Run an agent session end to end and read the reply. A session is a named
conversation with an agent: you choose the identifier, and running the same
identifier again continues the same conversation. This first run needs nothing
but a credential — Albus supplies the model.

<CodeGroup>

```bash CLI
albus sessions run my-first-session \
  --prompt "In one sentence, what is a session?" \
  --agent-name demo \
  --model gemini-3.6-flash
```

```python Python
import os

from albus_sdk import Albus

with Albus(
    api_key=os.environ["ALBUS_API_KEY"],
) as albus:
    response = albus.sessions.run_session(
        id="my-first-session",
        user_prompt="In one sentence, what is a session?",
        agent_name="demo",
        agent={"model": {"name": "gemini-3.6-flash"}},
        wait_timeout_seconds=120,
    )

    print(response.result.message.content)
```

```typescript TypeScript
import { Albus } from "@albus-ts/sdk";

const albus = new Albus({
  security: { apiKey: process.env.ALBUS_API_KEY ?? "" },
});

const response = await albus.sessions.runSession({
  id: "my-first-session",
  waitTimeoutSeconds: 120,
  body: {
    userPrompt: "In one sentence, what is a session?",
    agentName: "demo",
    agent: { model: { name: "gemini-3.6-flash" } },
  },
});

console.log(response.result.message?.content);
```

```bash cURL
curl --fail-with-body \
  --request POST "https://albus.sh/api/sessions/my-first-session?wait_timeout_seconds=120" \
  --header "Authorization: Bearer $ALBUS_API_KEY" \
  --header "Content-Type: application/json" \
  --header "Idempotency-Key: first-run-1" \
  --data '{
    "user_prompt": "In one sentence, what is a session?",
    "agent_name": "demo",
    "agent": { "model": { "name": "gemini-3.6-flash" } }
  }'
```

</CodeGroup>

<Note>
The wait makes the request long-poll until the assistant's reply is available:
`wait_timeout_seconds` over HTTP and in Python, `waitTimeoutSeconds` in
TypeScript, `--wait-timeout` in the CLI. Omit it and you wait up to 30 minutes,
the maximum; pass `0` to return as soon as the run is accepted — see [Run a
session](/guides/run-a-session#waiting-for-the-reply).
</Note>

The response is the session and the one message this invocation produced:

```json
{
  "session": {
    "id": "my-first-session",
    "state": "DONE",
    "invocation_count": 1,
    "agent_name": "demo",
    "agent_revision": "b7f3c1a9d2",
    "created_at": "2026-02-10T18:03:44Z",
    "updated_at": "2026-02-10T18:03:51Z"
  },
  "message": {
    "cursor": 2,
    "invocation_id": "3f7c1e02-9a4b-4d81-b6de-5c2a70f18e44",
    "role": "assistant",
    "content": "A session is a named, ongoing conversation with an agent.",
    "created_at": "2026-02-10T18:03:51Z"
  }
}
```

`message` is the assistant's reply, and is absent when the invocation has not
answered yet — `wait_timeout_seconds=0`, or a wait that returned first. The whole
conversation comes from `GET /sessions/{id}`, whose `messages` array holds every
turn. The CLI prints the same object plus the run's `invocation_key`, taken from
the response header.

## Continue the conversation

Run the same session identifier again. The agent sees the earlier turns.

```bash
albus sessions run my-first-session \
  --prompt "Now say that again in five words." \
  --agent-name demo \
  --model gemini-3.6-flash
```

## Read it back

```bash
albus sessions list
albus sessions get my-first-session
albus sessions audit my-first-session --limit 20
```

`get` returns the messages; [`audit`](/guides/audit-log) returns what happened
inside the runs — model calls, tool calls, and outcomes. `GET /traces` and
`GET /traces/{invocation_key}` return the same invocations as spans, across
sessions, with token usage — see [run a
session](/guides/run-a-session#reading-an-invocation-back).
