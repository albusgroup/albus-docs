Albus runs agents behind one HTTP API. A **session** is a named conversation:
you pick the id, and running the same id again continues it. One `POST` runs a
turn and returns the reply. Everything the agent did is recorded as a trace and
in the session's audit log.

Read as much of https://docs.albus.sh as you need. Every page is Markdown with
`.md` appended to its URL; https://docs.albus.sh/llms.txt is the map. This page
is enough to write working code.

## Limits

- **One run per session at a time.** A second one gets `423`. Run concurrently
  across session ids, not inside one.
- **Runs cost credits.** `402` means the organization's balance is empty. Stop
  and tell the user; retrying does not help.
- **Bounded retries.** Albus retries a crashed run up to three attempts, then
  fails it with `502`.
- **Observability is traces plus the per-session audit log.** Spans are kept 90
  days.

## Authentication

Base URL `https://albus.sh/api`. Every request carries
`Authorization: Bearer <credential>`. There are two credentials:

| Credential | Looks like | Get it | Use it for |
|---|---|---|---|
| Organization API key | `alb-…` | `albus tokens create NAME` (browser session required) or the console | Scripts, CI, SDKs. Set `ALBUS_API_KEY`; the CLI and both SDKs read it. |
| Browser session | — | `albus login` | Interactive CLI use, and minting API keys |

`/tokens` and `/invites` identify *you* and need the browser session.
Everything else accepts either.

### Set up the CLI

```bash
curl -fsSL https://albus.sh/install.sh | sh     # Windows: irm https://albus.sh/install.ps1 | iex
albus status
```

`status` prints JSON: `credential` is `api_key`, `session`, or `none`;
`authenticated` says whether Albus accepted it. It exits 0 either way; read the
JSON. If `authenticated` is true: with `credential: "api_key"` skip to the SDK
install; with `credential: "session"` skip the sign-in and mint an API key
below. If it is false, sign in.

You cannot complete a browser sign-in yourself. Print the URL, let the user
open it:

```bash
albus login --no-browser
```

The command prints the URL on its own line and blocks up to 180 seconds. The
redirect goes to `127.0.0.1:8484-8487` on the machine running the CLI; if the
user's browser is elsewhere, they forward those ports (`ssh -L 8484:localhost:8484
-L 8485:localhost:8485 -L 8486:localhost:8486 -L 8487:localhost:8487 user@host`)
or set `ALBUS_API_KEY` here instead.

Verify with `albus whoami`, then mint a key for code:

```bash
albus tokens create local-dev        # the token field is shown once
export ALBUS_API_KEY="alb-…"
```

Never write the key into source, committed config, or a shell profile you did
not create for it.

## The API

| Do | HTTP | Python | TypeScript |
|---|---|---|---|
| Run or resume a session | `POST /sessions/{id}` | `sessions.run_session` | `sessions.runSession` |
| Read a session and its messages | `GET /sessions/{id}` | `sessions.get_session` | `sessions.getSession` |
| List sessions | `GET /sessions` | `sessions.list_sessions` | `sessions.listSessions` |
| Cancel the running turn | `POST /sessions/{id}/cancel` | `sessions.cancel_session` | `sessions.cancelSession` |
| Delete a session | `DELETE /sessions/{id}` | `sessions.delete_session` | `sessions.deleteSession` |
| Read the audit log | `GET /sessions/{id}/audit` | `sessions.get_session_audit` | `sessions.getSessionAudit` |
| List runs across sessions | `GET /traces` | `traces.list_traces` | `traces.listTraces` |
| Read one run and its spans | `GET /traces/{invocation_key}` | `traces.get_trace` | `traces.getTrace` |
| Agents and their revisions | `GET /agents`, `/agents/{name}`, `/agents/{name}/revisions/{revision}` | `agents.*` | `agents.*` |
| Secrets | `/secrets`, `/secrets/{name}` | `secrets.*` | `secrets.*` |
| Memory groups | `/memorygroups`, `/memorygroups/{group}`, `/memorygroups/{group}/memories/{id}` | `memories.*` | `memories.*` |
| Models Albus serves | `GET /models` | `models.list_models` | `models.listModels` |
| Who am I | `GET /whoami` | `auth.whoami` | `auth.whoami` |

The CLI mirrors it: `albus sessions run|get|list|cancel|delete|audit`, `albus
traces list|get`, `albus agents list|get|revision`, `albus secrets
create|get|list|update|delete`.

### Run or resume a session

`POST /sessions/{id}` with `user_prompt`, `agent_name`, and `agent`. If the
session does not exist it is created; if it does, the prompt is appended to the
conversation and the model sees every earlier turn.

<CodeGroup>

```python Python
response = albus.sessions.run_session(
    id="support-1234",
    invocation_key="support-1234-triage-1",
    user_prompt="Customer says login fails after the password reset. Triage it.",
    agent_name="support-triage",
    agent={
        "model": {"name": "gemini-3.6-flash"},
        "system_prompt": "You triage support tickets. Be terse.",
        "tools": {"web_search": {}, "terminal": {}},
    },
    wait_timeout_seconds=300,
)
print(response.result.session.state)          # DONE
print(response.result.message.content)        # the reply to this prompt
```

```typescript TypeScript
const response = await albus.sessions.runSession({
  id: "support-1234",
  invocationKey: "support-1234-triage-1",
  waitTimeoutSeconds: 300,
  body: {
    userPrompt: "Customer says login fails after the password reset. Triage it.",
    agentName: "support-triage",
    agent: {
      model: { name: "gemini-3.6-flash" },
      systemPrompt: "You triage support tickets. Be terse.",
      tools: { webSearch: {}, terminal: {} },
    },
  },
});
console.log(response.result.session.state);   // DONE
console.log(response.result.message?.content);
```

</CodeGroup>

The response is the `session` plus the one `message` this run produced. The
whole conversation is `GET /sessions/{id}`.

**`wait_timeout_seconds`** (query; `waitTimeoutSeconds` in TypeScript). Block
up to this many seconds for the reply. Omit to wait 30 minutes, the maximum.
`0` returns as soon as the run is accepted, with `session.state == "RUNNING"`
and no `message`; poll `GET /sessions/{id}` until `state` changes. A timeout is
`504` and the run keeps going. Both SDKs default to 1800 and set a 31-minute
transport timeout, so a waiting call needs no client configuration.

**`agent`** is the configuration. Every distinct one under an `agent_name` is
recorded as a **revision** (`session.agent_revision`), so you never create an
agent, you name one. Fields:

| Field | Meaning |
|---|---|
| `model.name` | One of `GET /models`, or any model with `model.provider` set to your own account. |
| `model.provider` | Your own provider credential, as a secret reference. Omit to use the model Albus supplies. |
| `system_prompt` | Instructions. Albus prepends the current date and time. |
| `tools` | Object, not list. `{"web_search": {}}` offers web search; `{"terminal": {}}` a persistent Linux sandbox. Omit a tool and the model never sees it. |
| `mcp_servers` | `[{name, url, headers, allowed_tools}]`. Streamable HTTP only. The model sees tools as `<name>__<tool>`. |
| `memory` | `{"group": "support", "generation": ["end_of_invocation", "agent"]}`. Durable memory shared by every run with the same group, in any session. |
| `max_steps` | Cap on model steps per run. |
| `output_format` | JSON Schema the reply must satisfy. Every object needs `"additionalProperties": false` and every property in `required`. |

Credentials are never inlined. Store them (`albus secrets create NAME`) and
reference them as `albus.sh/secrets/<name>` in `headers` or
`model.provider.credential`. Albus resolves the reference when the run starts;
the value never appears in a response, a revision, or the audit log.

### Idempotency and retries

Every run has an **invocation key**. Send it as `invocation_key`
(`invocationKey`), which is the `Idempotency-Key` header over HTTP. The
response returns the effective key in the same header, generated if you sent
none. The key is unique in your organization and is how you read the run back:
`GET /traces/{invocation_key}`.

| You send | Albus does |
|---|---|
| A new key | Starts a run |
| The same key, same body | Re-attaches to that run and returns its current state, even after it finished or failed |
| The same key, different body | `409` |
| A different key while the session is already running | `423` |
| No key | Starts a run you cannot retry safely |

Rules:

- **Always send a key for unattended work.** Derive it from the thing that
  must happen exactly once: the event id, or the session id plus a turn
  counter (`support-1234-triage-1`). Never a timestamp or a fresh random value
  per attempt; each one starts another run.
- **Retry `504` with the same key.** The run is still going; the same key waits
  on it. Retry connection failures the same way.
- **Do not retry `400`, `402`, `409`, `423`, or `502` as-is.** They will fail
  the same way. To rerun a failed run, use a **new** key.
- **Pick session ids you already have.** The ticket, the pull request, the job.
  `^[0-9a-zA-Z._:-]+$`, 2–100 characters. Reuse continues; a new id starts over.

<CodeGroup>

```python Python
from albus_sdk import errors

for _ in range(3):
    try:
        response = albus.sessions.run_session(
            id="support-1234",
            invocation_key="support-1234-triage-1",
            user_prompt="Triage this ticket.",
            agent_name="support-triage",
            agent={"model": {"name": "gemini-3.6-flash"}},
            wait_timeout_seconds=120,
        )
        print(response.result.message.content)
        break
    except errors.ErrTimeout:
        continue                       # 504: still running, same key re-attaches
else:
    print("still running; poll GET /sessions/support-1234")
```

```typescript TypeScript
import { ErrTimeout } from "@albus-ts/sdk/models/errors";

for (let attempt = 0; attempt < 3; attempt++) {
  try {
    const response = await albus.sessions.runSession({
      id: "support-1234",
      invocationKey: "support-1234-triage-1",
      waitTimeoutSeconds: 120,
      body: {
        userPrompt: "Triage this ticket.",
        agentName: "support-triage",
        agent: { model: { name: "gemini-3.6-flash" } },
      },
    });
    console.log(response.result.message?.content);
    break;
  } catch (error) {
    if (!(error instanceof ErrTimeout)) throw error; // 504: same key re-attaches
  }
}
```

</CodeGroup>

### Status codes

| Status | Meaning | Do |
|---|---|---|
| `400` | Invalid prompt or configuration | Fix the request |
| `401` | Credential rejected | `albus status`, re-authenticate |
| `402` | No credit balance | Stop; tell the user |
| `404` | No such session, secret, agent, or revision | Check the id |
| `409` | Key reused with a different body, or cancel with nothing running | New key, or resend the original body |
| `410` | The run was canceled while you waited | Nothing to retry; a new key runs again |
| `423` | The session is running another prompt | Wait, re-send the running key to attach, or use another session id |
| `502` | Every attempt failed; body has `kind` and `detail` | Read the trace; a new key reruns |
| `503` | Temporarily unavailable; may carry `Retry-After` | Wait and retry |
| `504` | Wait elapsed; the run continues | Same key again, or poll |

Python raises `errors.AlbusError` subclasses (`ErrTimeout`, `ErrLocked`,
`ErrConflict`, `ErrInvocationFailed`, `ErrInvocationCanceled`,
`ErrInsufficientCredit`, …) with `.status_code`. TypeScript throws the same
names from `@albus-ts/sdk/models/errors` with `.statusCode`.

### Read a session and its messages

`GET /sessions/{id}` returns `session` and `messages` in chronological order.
Each message has `role` (`user` or `assistant`), `content`, the
`invocation_key` that produced it, and a `cursor`.

<CodeGroup>

```python Python
page = albus.sessions.get_session(id="support-1234", limit=100)
print(page.session.state, page.session.invocation_count, page.session.agent_revision)
for message in page.messages:
    print(message.role, message.content)
while len(page.messages) == 100:
    page = albus.sessions.get_session(
        id="support-1234", after=str(page.messages[-1].cursor), limit=100
    )
    for message in page.messages:
        print(message.role, message.content)
```

```typescript TypeScript
let page = await albus.sessions.getSession({ id: "support-1234", limit: 100 });
console.log(page.session.state, page.session.invocationCount, page.session.agentRevision);
for (const message of page.messages) console.log(message.role, message.content);
while (page.messages.length === 100) {
  page = await albus.sessions.getSession({
    id: "support-1234",
    after: String(page.messages.at(-1)!.cursor),
    limit: 100,
  });
  for (const message of page.messages) console.log(message.role, message.content);
}
```

</CodeGroup>

`session.state` is `RUNNING` while a turn is in flight, otherwise `DONE`,
`FAILED`, or `CANCELED` for the last one. `session.current_invocation_key` is
the running turn's key while `RUNNING`.

### List sessions

`GET /sessions` returns sessions ordered by their most recent matching run.
Filters: `agent_name`, `agent_revision` (needs `agent_name`), `status`
(`RUNNING`, `DONE`, `FAILED`, `CANCELED`), `invocation_key`, `since`, `until`
(default: the last 31 days). Page size `limit` is 25 by default, 100 at most.

<CodeGroup>

```python Python
page = albus.sessions.list_sessions(agent_name="support-triage", status="FAILED")
for session in page.sessions:
    print(session.id, session.state, session.updated_at)
```

```typescript TypeScript
const page = await albus.sessions.listSessions({
  agentName: "support-triage",
  status: "FAILED",
});
for (const session of page.sessions) console.log(session.id, session.state, session.updatedAt);
```

</CodeGroup>

### Cancel

`POST /sessions/{id}/cancel` asks the running turn to stop and returns `202`
once the request is accepted; the run ends shortly after with state
`CANCELED`. `409` means nothing was running. A caller still waiting on the run
gets `410`.

<CodeGroup>

```python Python
albus.sessions.cancel_session(id="support-1234")
```

```typescript TypeScript
await albus.sessions.cancelSession({ id: "support-1234" });
```

</CodeGroup>

`DELETE /sessions/{id}` removes the session and its messages. Traces and audit
events are not messages; they stay.

### Traces and spans

Every run is a **trace**: its status, timing, failure, and its **spans**: the
run (`invocation`), each `step`, the `model_call` in each step, and every
`tool_call`, each with `input`, `output`, timings, and token `usage`. This is
how you find out what the agent did.

`GET /traces` lists runs across sessions, newest first, without spans.
Filters: `agent_name`, `agent_revision`, `status`, `session_id`, `since`,
`until`. `limit` defaults to 10, max 100.

`GET /traces/{invocation_key}` returns one run with its spans. `attempts=final`
(default) returns the last attempt's spans; `attempts=all` includes superseded
attempts, whose tool calls still had their effects. `payloads=false` drops
inputs and outputs and raises the page size from 25 to 500.

<CodeGroup>

```python Python
failed = albus.traces.list_traces(agent_name="support-triage", status="FAILED", limit=10)
for summary in failed.traces:
    print(summary.invocation_key, summary.session_id, summary.started_at)

trace = albus.traces.get_trace(invocation_key="support-1234-triage-1").result
print(trace.status, trace.failure)
for span in trace.spans:
    print(span.id, span.type, span.name or "", span.status)
    if span.type == "tool_call":
        print("  in:", span.input)
        print("  out:", span.output)
```

```typescript TypeScript
const failed = await albus.traces.listTraces({
  agentName: "support-triage",
  status: "FAILED",
  limit: 10,
});
for (const summary of failed.traces) {
  console.log(summary.invocationKey, summary.sessionId, summary.startedAt);
}

const { result: trace } = await albus.traces.getTrace({
  invocationKey: "support-1234-triage-1",
});
console.log(trace.status, trace.failure);
for (const span of trace.spans) {
  console.log(span.id, span.type, span.name ?? "", span.status);
}
```

</CodeGroup>

Span ids read as a path: `inv3` is the third run of the session,
`inv3.attempt1.step2.tool1` the first tool call of its second step. Payloads
over the limit are cut with an `[omitted: N of M bytes; sha256=…]` marker. A
`FAILED` span carries `error`; a failed run carries `failure` with `kind`
(`crash`, `no_progress`, `interrupted`, `internal`) and `message`. After 90
days `spans_expired` is true and the run itself still reads.

Debugging loop: run, read the trace, change the prompt or a tool, run again
with a **new** key, compare. From a shell, `albus traces get KEY` and `albus
traces list --agent-name NAME --status FAILED` print the same.

### Audit events

`GET /sessions/{id}/audit` is the security record of a session: an immutable,
chronological list of everything that happened, arguments and results
included. Each event has `id`, `session_id`, `invocation_key`,
`agent_revision`, `type`, `event_time`, and a `payload` shaped by its type.

| `type` | Records |
|---|---|
| `agent_invocation` | The request that started a run |
| `agent_step` | One step, how it ended, how long it took |
| `model_call` | A model call and the tool calls it requested |
| `tool_call` | An executed tool call: arguments, response, MCP server URL |
| `invocation_succeeded` / `invocation_failed` | How the run ended |
| `harness_exit` | The execution environment exited |

Events written before the rename keep their old names (`run_succeeded`,
`run_failed`, `llm_call`, `tool_result`); filter on both when you care about
history. Model output, tool arguments, and tool output are stored truncated,
with `contentBytes`, `contentSha256`, and `contentTruncated`, so a stored value
can be checked against the original. Secrets never appear.

<CodeGroup>

```python Python
page = albus.sessions.get_session_audit(id="support-1234", limit=100)
for event in page.events:
    if event.type == "tool_call":
        print(event.event_time, event.agent_revision, event.payload)
```

```typescript TypeScript
const page = await albus.sessions.getSessionAudit({ id: "support-1234", limit: 100 });
for (const event of page.events) {
  if (event.type === "tool_call") console.log(event.eventTime, event.agentRevision, event.payload);
}
```

</CodeGroup>

The audit log is per session. For the same events across sessions, filtered
by agent, revision, status, or time, use traces. From a shell: `albus sessions
audit ID --limit 50`.

### Pagination

Every list is cursor-paged with `after` and `limit`.

- **List responses** (`/sessions`, `/traces`, `/sessions/{id}/audit`, spans in
  `/traces/{key}`) return `next_cursor` when there is more. Pass it as `after`.
  No `next_cursor`, no more pages.
- **Session messages** (`/sessions/{id}`) have no `next_cursor`. Pass the last
  message's `cursor` as `after`; a page shorter than `limit` is the end.
- `limit` maxima: 100 for sessions and traces, 1000 for messages and audit
  events, 500 for spans without payloads and 25 with.

<CodeGroup>

```python Python
after = None
while True:
    page = albus.sessions.get_session_audit(id="support-1234", after=after, limit=500)
    for event in page.events:
        print(event.type)
    after = page.next_cursor
    if not after:
        break
```

```typescript TypeScript
let after: string | undefined;
do {
  const page = await albus.sessions.getSessionAudit({ id: "support-1234", after, limit: 500 });
  for (const event of page.events) console.log(event.type);
  after = page.nextCursor;
} while (after);
```

</CodeGroup>

## Fan out

Concurrency is across sessions. One key per unit of work, one session per
work item.

```python Python
import asyncio
import os

from albus_sdk import AsyncAlbus

TICKETS = ["support-1", "support-2", "support-3"]


async def triage(albus: AsyncAlbus, ticket: str) -> str:
    response = await albus.sessions.run_session(
        id=ticket,
        invocation_key=f"{ticket}-triage-1",
        user_prompt="Triage this ticket.",
        agent_name="support-triage",
        agent={"model": {"name": "gemini-3.6-flash"}},
        wait_timeout_seconds=300,
    )
    return response.result.message.content


async def main() -> None:
    async with AsyncAlbus(api_key=os.environ["ALBUS_API_KEY"]) as albus:
        for reply in await asyncio.gather(*(triage(albus, t) for t in TICKETS)):
            print(reply)


asyncio.run(main())
```
