---
title: Private beta limitations
description: What Albus does not do yet, and what to design around.
---

Read this before designing anything against Albus. Everything below is
deliberate scope in the private beta, not a defect, and each item changes what
you should ask an agent to do.

## Quota: 20 session runs per organization

Every invocation counts, across every session, for the lifetime of the
organization. Once the cap is reached, a run returns `429` and nothing executes:

```json
{ "message": "organization invocation quota exceeded" }
```

Email [carlo@albus.sh](mailto:carlo@albus.sh) to have the cap raised. Do not
retry a `429` in a loop; it will not clear on its own.

## No usage or spend surface

Albus meters what your invocations spend, but there is no API or console page
that reports usage, credits, or a bill yet, and nothing to top up. What you can
read today is token usage on an invocation's trace — per attempt, and per span. Email [carlo@albus.sh](mailto:carlo@albus.sh) for anything else about
consumption.

## One invocation at a time per session

A session runs a single invocation at a time; a second one gets `423` until the
first ends. Concurrency belongs across sessions — that is what caller-chosen
session ids are for.

A run also loads at most the session's 1000 most recent messages as history.
Older turns fall out, so anything that has to survive them belongs in a [memory
group](/guides/run-a-session#memory) or in your own system.

## Retries are bounded, and a failed invocation is not resumed

Albus retries an invocation that crashes, up to three attempts. Past that the
invocation fails and its work is lost; the API answers `502` with the failure
kind and detail, and the attempts are on its trace.

Recovering from there is your call: reusing the failed invocation's key
re-attaches to it and returns the same failure, so start a new run with a **new**
key. Keep runs short enough that losing one is cheap.

## Observability stops at your own invocations

[Traces](/guides/run-a-session#reading-an-invocation-back) cover invocations
across sessions — filtered by agent, revision, status, session, and time, with
each attempt's token usage — and the [per-session audit log](/guides/audit-log)
records every model call and tool call with its payloads. What is not there:
metrics, dashboards, alerting, and full-text search over payloads. Spans are also
kept for 90 days from the invocation's start, after which the invocation stays
readable and its spans do not.

Neither traces nor memories have CLI commands yet — read them from the SDKs, over
HTTP, or in the console.

## Roadmap

A higher run cap, a usage and billing surface, richer observability, and durable
execution are all post-beta work. Tell
[carlo@albus.sh](mailto:carlo@albus.sh) which one blocks you — that is what
orders the list.
